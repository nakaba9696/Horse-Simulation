# ゲームの画面と騎乗の手ざわり

画面や騎乗の手ざわりに触る仕事は、この手順で進める。決まりの本文は2つの文書にある。このスキルは、どれを読み、どう作り、どう確かめるかをまとめたもの。

- 騎乗の外の画面：`docs/UI.md`（テーマ・色の表・字・部品・画面ごとの配置・選ぶ操作・物差し）
- 騎乗中：`docs/FEEL.md`（入力から反応まで・カメラと揺れ・光と音と振動・計器・ゴール後の流れ・物差し）
- 3D の馬：`docs/HORSE3D.md`

## 1. 始める前に読む
1. 触る画面の節を `docs/UI.md` か `docs/FEEL.md` で読む。持ち主の声（文書の頭）も読む。
2. いまの点を見る（`docs/UI.md` 6 の表、`docs/FEEL.md` 6 の自己採点）。不合格の画面と「次に直す所」が先。
3. 見た目の方向を決めるときは、使えるなら Skill `frontend-design:frontend-design` を読む（決め打ちの見た目を避ける考え方）。撮った絵の講評には `design:design-critique` が使える。使えないセッションでは飛ばしてよい。どちらもこのゲームの決まりより下。

## 2. 作るときの決まり（要点。本文は文書）
- 部品を先に使う。新しい形を作る前に、共通の部品（JS は `js/ui/uikit.js`・`css/ui.css`、Godot は `godot/ui/theme.gd`）で作れないかを見る。1つの画面だけ違う作りにしない。
- 色は役目の名前で使い、値を直書きしない（`docs/UI.md` の色の表）。テーマは深緑と金・明朝の題字。
- 参考の作品の写しにしない。手ざわり（並べ方・切り替え方・情報の量）だけ取る。名前・画像・動画はリポジトリに入れない。
- 主な操作は1つを金にし、最初のカーソルをそこに置く。確かめの画面は「やめる」から。もどるとカーソルの位置に戻す。タブは Q/E・LB/RB。
- 主な情報と主な操作はスクロールしないで見える（出走表は 18 頭が 1600×1000 の1画面）。
- 騎乗中は操作の結果を文字で出さない。光・揺れ・音・振動・計器・レーダーの印で返す。出すなら短い英語の合図だけ。
- 揺れは3Dのカメラだけを、減衰する正弦で小さく短く（`docs/FEEL.md` 2 の上限）。画面の箱や計器は揺らさない。
- 待ちはどれもボタンで飛ばせる。結果の瞬間は一瞬止めて、少し流してから出す。

## 3. 撮って、採点して、直す（push の前に必ず）
1. 直すたびに 1600×1000 で撮る。
   - JS の画面：`NODE_PATH=$(npm root -g) node tools/shot_ui.js <出力先>`
   - JS の騎乗：`NODE_PATH=$(npm root -g) node tools/shot_feel.js <出力先> after`
   - Godot：`docs/GODOT.md` の撮り方（決まった刻みで模擬を進めて撮る）
2. 撮った絵を自分で見て、文書の物差しで点を付ける。
   - 画面：`docs/UI.md` 6 の6つを 0〜2 点。12 点のうち 10 点以上、0 点なしで合格。
   - 騎乗：`docs/FEEL.md` 6 の5つを 0〜4 点。16 点以上、どの軸も 3 点以上で合格。
3. 合格に届くまで直して撮り直す。届いたら、文書の点の表を書き直す。
4. `node tests/run.js` が「0 failed」で、`n passed` が前より減っていないことを確かめてから push する。
5. 報告には、絵の場所と、画面ごとの点（前と後）を入れる。

## 4. 持ち主の新しい指摘を受けたら
- 文書（`docs/UI.md`・`docs/FEEL.md`）の「持ち主の声」と該当の節に書き足し、物差しで測れる形にする。
- 一般化できることは知恵袋（KnowledgeBase の `skills/game-design`）にも足す（CLAUDE.md の手順）。
