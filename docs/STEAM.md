## 3. 実績
### 入れ口
- `godot/core/hs_achieve.gd` の `HSAchieve.unlock(id)` が1か所の入れ口。いまは解いた id を覚えるだけで何もしない。
- Steam につなぐときは、起動したあとに1度だけ `HSAchieve.backend = func(id): Steam.setAchievement(id); Steam.storeStats()`（GodotSteam の名前）を渡す。呼ぶ側は変えなくてよい。
- 自分の馬がトロフィーを手にしたとき（`HSTrophy.give`。レースの勝ち・着差の合計・G1 の連勝・GF のどれでも）に呼ぶ。ほかの馬では呼ばない。同じ id は1回の起動で1度だけ。
- 「つづきから」では、セーブにあるトロフィーの分をもう一度呼ぶ（`HSAchieve.sync_from_world`）。SDK を入れる前のセーブで取ったトロフィーも、あとで Steam の実績に載る（Steam は解いた実績を二度解いても何も起きない）。
- 実績はセーブに入れない（覚えるのは Steam の側）。遊びの結果（乱数・世界の状態）には触らない。
- 確かめ：`godot/tests/test_settings.gd`（三冠がそろうと `TROPHY_TRIPLE` が呼ばれる・二度は呼ばない・ほかの馬では呼ばない・backend に渡る・つづきからで呼び直す・40個で id が英大文字と数字と _ だけ）。

## 4. クラウドセーブ（Steam の自動クラウド）
### いまの置き場所（`user://`）
| ファイル | 中身 | クラウドに |
|---|---|---|
| `save.json` | セーブの本体（`UiFlow.save_path`。週を締めるたびに書く） | 入れる |
| `hall/save/<馬の id>.json` | 殿堂入りした馬の1走ごとの記録（セーブの枠ごと。`HSHall`） | 入れる |
| `replays/<id>.json` | 自分で乗ったレースのリプレイ（20本まで） | 入れる（1本 数百KB。要らなければ外してよい） |
| `settings.cfg` | 設定（画面の大きさ・音量・振動・割り当て） | 入れない（PC ごとに違う。解像度が別の PC に移ると困る） |
| `demo_replays/`・`logs/`・`shader_cache/`・`vulkan/` | 撮影の見本・Godot のログ・シェーダーの貯め置き | 入れない |

### 確かめたこと
- どれもふつうのファイルで、`user://` の下にまとまっている。Steam の自動クラウドは「決まったフォルダの下の、決まった名前の型のファイル」を同期するので、**このままの形で同期できる**。ゲームの中に Steam のクラウドの API を呼ぶ処理は要らない。
- 置き場所：Windows では `%APPDATA%\Godot\app_userdata\ターフの系譜\`（`project.godot` の `config/name`）。日本語のフォルダ名は Steam の自動クラウドでも使えるはずだが、英語の名前にするほうが確実（推し）：`project.godot` に `config/use_custom_user_dir=true`・`config/custom_user_dir_name="TurfLineage"` を足すと `%APPDATA%\TurfLineage\` になる。いまの手元のセーブは場所が変わる（発売前なので、持ち主の手元のセーブだけ移せばよい）。
- 自動クラウドの登録の案（Steamworks の「Steam Cloud」）：ルート `WinAppDataRoaming`・サブフォルダ `TurfLineage`（英語の名前にした場合）。パターンは `save.json`・`hall/*`（サブフォルダも）・`replays/*.json`。1人あたりの量は 100MB・ファイル数 500 で足りる。
- 気をつけること：セーブは上書きで書いている（`FileAccess.open(WRITE)`）。書いている途中で落ちるとファイルが壊れ、壊れたものが同期される。発売の前に「別の名前に書いてから入れ替える」に直すのが推し（小さな直し。`godot/ui/flow.gd` の `save`）。
- セーブの枠は1つ（`save.json`）。枠を増やすなら `save_*.json` の型で登録すれば同じ仕組みで同期できる（殿堂の記録は枠ごとのフォルダに分かれている）。

## 5. AI で作った内容の申告（ストアのページの質問票）
Steam は、作るときに AI で作った内容（絵・音・文など）と、遊んでいる間に AI で作る内容を申告させる。このゲームは**遊んでいる間に AI を呼ばない**（CLAUDE.md の決まり）ので、申告するのは作るときのものだけ。
| 中身 | 何で作ったか | 出典 |
|---|---|---|
| 画面の部品（ボタン・札・帯・飾り・アイコン20）と背景の絵7枚（`godot/assets/ui/*.png`） | 持ち主が GPT の画像生成で作った | `godot/CREDITS.md` |
| オーナーの顔の絵（`godot/assets/owners/*.webp`・表情4つ） | 持ち主が Stable Diffusion で作った（ほかのゲームのために作った絵を使う） | `assets/CREDITS.md` |
| 文（名馬の解説・オーナーの台詞・画面の文）とプログラム | AI の助け（Claude）で下書きし、出典で確かめて直した | 要確認：文やプログラムまで申告するかは、Steam の今の質問票の書き方で決める |
| 曲（BGM） | 自分で書いたプログラムで作った曲（`js/ui/audio.js` → `tools/render_bgm.js`） | AI の生成ではない |
| 3D の形・質感・空 | CC0・CC-BY の素材（Quaternius・Poly Haven・abhayexe） | `godot/CREDITS.md` |

申告の文の案：「画面の部品・背景の一部と、登場人物（オーナー）の顔の絵は、開発者が画像生成 AI で作り、手で選んで整えたものです。ゲームの中で AI が内容を作ることはありません。」

## 6. 年齢の区分・言語
- 中身：競馬（実在の馬名・レース名・競馬場名。騎手・馬主・調教師は架空）。馬券などの賭けは無い。暴力・血・性的な描写は無い。お金は賞金と馬の売り買いだけ（本物のお金で買う物は無い）。
- Steam の質問票は「該当なし」で答えられる見込み（全年齢）。実在の馬名を使うことは年齢の区分には関わらない。名前の権利は別の話として持ち主が判断する（いまの決まり：馬名・レース名・競馬場名は実名）。
- 言語：画面の文は日本語と英語（設定で切り替え。`docs/I18N.md`）。声は無い。騎乗中の短い合図（START・GOOD START・視点の名前・着順）はどちらでも英語。

| 空き容量 | 2GB | 2GB |
- 測っていない所が多いので「案」。GPU のある Windows の機械で 1920×1080 の 1コマ を測ってから決める（下の 8）。
- 3D は Forward+（Vulkan）。影の地図が 8192（`project.godot`）なので、弱い GPU では重い見込み。設定の画面の解像度を下げると、フルスクリーンでは 3D を描く細かさが下がる（`scaling_3d_scale`）。影の質を選ぶ設定は、測ってから足すか決める。

## 8. 重さ（騎乗のレース・16頭）
測った機械：この container（Intel Xeon 2.8GHz・4コア・GPU 無し。描くのは CPU の Vulkan＝llvmpipe）。2026-10-21。道具は `godot/tools/bench_frame.gd`（レースを 20 秒まで早送りしてから、本当にコマを回して測る。vsync は切る）と `godot/tools/bench_view.gd`。

| 測ったもの | 1コマ | 60fps（16.7ms）に |
|---|---|---|
| 画面なしで回す1コマ（模擬・馬の形・騎手・カメラ・計器の更新。`bench_frame.gd` を headless で。GDScript の模擬） | 平均 7.66ms・95% 11.6ms | 届く |
| 同じ（C++ の模擬） | 平均 7.29ms・95% 11.1ms | 届く |
| 騎乗のカメラの更新だけ（`bench_view.gd`。600コマの平均） | 5.0ms | 届く |
| 描く所の CPU の時間（1600×1000・`RenderingServer` の測り。描く命令を作る分） | 2.0ms | 届く |
| 描く所の GPU の時間 | **測れない**（この機械は GPU が無く、CPU で描くので 1コマ 5.5 秒かかる。GPU の重さの目安にならない） | 測れない |

- CPU の側は 1コマ 9〜10ms ほど（更新 7〜8ms ＋描く命令 2ms）で、60fps の 16.7ms に届く。95% でも 13ms ほど。CPU は弱めのサーバーの1コアなので、ふつうの PC ではもっと速い見込み。
- 模擬は C++ でも GDScript でもほとんど変わらない（騎乗中は 1コマ に 0〜1 刻みなので、模擬は重さの主ではない）。重さの主は、馬16頭の形（骨）・騎手・カメラ・計器の更新。
- GPU の側（影の地図 8192・MSAA 2x・草の質感・16頭の毛の房）は、GPU のある Windows の PC で測る必要がある。測り方：`godot --path godot -s res://tools/bench_frame.gd -- --frames=300 --res=1920x1080`（結果は2行で出る）。最低（GTX 960 くらい）と推奨（GTX 1660 くらい）の2台で測り、7 の目安を決める。
- 届かなかったときに下げられる所：影の地図（8192 → 4096）・MSAA・フルスクリーンの解像度（設定の画面で下げると 3D を描く細かさが下がる）。
