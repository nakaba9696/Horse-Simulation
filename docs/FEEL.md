# 騎乗の手ざわり（FEEL）

騎乗の画面の「手ざわり」の決まり。JS 版（`js/ui/ride.js`・`js/ui/race3d.js` のカメラ・`js/ui/rumble.js`・`js/ui/audio.js` の効果音）の今の値と、Godot 版の騎乗を作るときの目標を書く。数は JS 版で入れた値（★）か、目標（◎）か、仮（仮）かを付ける。

持ち主の指摘（2026-10-16、そのまま）：「全体的に細かいところがひどい」「人間が遊ぶ手触りになってない」「ムチうつとガクガクゆれる」「パッドの移動十字キー？　横移動できない」「溜めてるとか折り合ってるとか表示いらない」「折り合いゲージとかダサいのでもっときれいにして」「ゴールしたら少し走ってから順位表示して」。
持ち主の指摘（2026-10-17、Godot 版を遊んで）：「ジョッキー乗ってる姿が変」→ 騎手の乗り姿の決まりと物差しは `docs/HORSE3D.md` 9。
持ち主の指摘（2026-10-17）：「スタートのカウントダウンいらない　目押しで」→ 数え（3・2・1 の数字と音）をやめ、ゲートの上の灯（前触れ）を見て開く瞬間に合わせて押す形にした（下の「ゲート（目押し）」）。
持ち主の指摘（2026-10-20、テスト版7）：「脚質は左下に。左上は順位と残りmだけ」「FIGHT・WHIP・縦のメーターは意味が分からない」「折り合いのゲージをもっと分かりやすく」「左右の動きが反対」「L2・R2 のカメラが速すぎ、角度もおかしい」「カメラに合わせて騎手も顔を向ける」「FIGHT いらない。折り合いゲージとか別で表現して」「WHIP いらない」「ムチどっちで打っても変わらないから無駄な情報増やさないで」→ 計器（4）・左右を見る（2）・進路の左右（1）。
持ち主の決定（2026-10-22）：「全開に入ったことの知らせ方：組み合わせでお願いします　スピードゲージも最大にすれば良いと思います」→ 全開の知らせは計器の色・音・振動の組み合わせで、速さの計器は全開の間だけ最大まで振り切る（3・4・8「全開の知らせ」）。
持ち主の指摘（2026-10-22、そのまま）：「脚質の表示箇所左下の項目にまとめて　今浮いてるから」→ 脚質の矢印と帯を、丸い計器の上に浮いた別の板から、STAMINA・手綱と同じ板のいちばん上の段へ入れた（4 の表「脚質の矢印」。テスト `godot/tests/test_hud_layout.gd`）。

### ゲート（目押し）
模擬の決まりは `S.GATE`（`js/core/racesim.js`。GDScript の `HSSim.GATE`・C++ の `G_*` も同じ値で、一致テストで確かめる）。秒はレースの秒（画面は実時間の 1.35 倍で進むので、実時間はこの値を 1.35 で割る）。
| 項目 | 値（レースの秒） | 実時間 | ねらい |
|---|---|---|---|
| ゲートで待つ秒 | ★ 2.2＋1.6×くじ（2.2〜3.8）。くじはレースの種から（`S.gateWaitOf`。種の乱数は進めない） | 1.6〜2.8 秒 | 毎回少し違うので、ゲートに入ってからの秒を覚えて押せない |
| 前触れ（灯） | ★ 開く 0.8 秒前に、ゲートの上の灯（枠ごと）がつき、扉が 0.3 秒だけ小さく鳴る。灯は開いて 0.4 秒で消える | 0.59 秒前 | 灯からの間合いはいつも同じ。灯を見て拍子を取れば狙える |
| GOOD | ★ 開く 0.12 秒前〜開いて 0.1 秒（開く前の押しは開いた瞬間に受け付ける） | 163ms の幅 | 開いてから見て押すと、人の反応（およそ 0.2 秒＝レースの 0.27 秒）では間に合わない |
| ふつう・出遅れ | ★ GOOD の後は押した時刻に出る。0.5 秒より遅いと出遅れ（脚を使う）。押さなければ 0.9 秒で出遅れ | − | |
| 早押し | ★ 開く 0.12 秒より前に押すと馬が煽る（気分＋4×気性の荒さ）。そのスタートは GOOD にならず、0.35 秒より早くは出られない | − | 漫然と押す・連打では取れない |
返し方：早押しは文字を出さず、馬が頭を上げ（0.5 秒）・鼻息（JS）・振動・小さな揺れで返す。GOOD START・LATE START は開いた瞬間に英語の合図で出す。
持ち主の指摘（2026-10-17、古典的な騎手が主役の3D競馬ゲームの騎乗の動画を見せて）：「馬のモーションや操作感これ参考にしてブラッシュアップして　馬の操作感、ジョッキーのモデル、スタート後の挙動とか参考になると思う」「操作感は生き物に乗ってる手応えがほしい」→ カメラの構図（2）・生き物に乗る手応えと拍子・ゲートを出たあと（8）。

## 0. 元にしたもの（作品の名前・絵・文はリポジトリに入れない）
- **古典的な騎手が主役の3D競馬ゲーム**：動画を落とす道具（yt-dlp）がこの環境に無く、動画は見られなかった。説明書の写し・攻略・レビュー・百科事典の記事から、次を確かめた（事実）：
  - 操作：十字の上＝スタートと手綱をしごく（1回で小さく、連打で大きく効く）、下＝引く、左右＝寄せる。左右のムチは別のボタン、持ち替えも別のボタン（逆の手のムチを押すと自動で持ち替える作品もある）。肩のボタンで左右を見る・レーダーの範囲。視点のボタン。振動に対応。
  - スタートは「ready」の合図が3回出て、4回目のころにゲートが開く（予告して合わせさせる）。
  - 後の作品では、スタミナの棒を「手応え」の棒に変えた（道中で溜めた手応えが終いの伸びになる）。速さの計器は「白と赤の境目が理想、赤は追いすぎ」の帯で見せる。馬の顔の表情で気持ちを見せる。
  - レビューでいちばん叩かれた点：計器が多く抽象的で「ごちゃごちゃ」、体で感じる興奮に欠ける、手綱とムチの感覚がつかみにくい。→ **計器は増やさず、まとめて、体（揺れ・音・振動・馬の動き）で返す**。
- **ゲームデザイナーの講座（UI・操作感の回）**：書き起こし・回の説明・週ごとのまとめ記事・コラムの英訳から（動画そのものは見ていない）。使った教え：
  1. 大事な瞬間は一瞬止める（ヒットストップ）。止める長さには上限。当たった側を強く揺らす。
  2. 揺れは最初が大きく、だんだん小さく（揺れの総量を先に決めて割り振る）。地面の上のものは左右に揺らす。カメラが近いほど小さく、遠いほど大きく。揺れている間も判定は動かさない。
  3. 押した感じ（重さ）はゲームの側で作る。構え（予備動作）は一瞬で大げさに。
  4. ボタン1つでできる遊びは4つ（連打・タイミング・反応・押し続けと離し）。→ しごく＝連打、ゲート＝タイミング、進路＝押し続け。
  5. ラグをなくす。1コマ（1/60 秒）を単位に考える。
  6. 効果音の大きさは派手さでなく大事さで決める。立ち上がりは強く、残響はほどほど。光を使いすぎると画面がぼやける。
  7. 言葉がなくても分かるように。大事なものとそうでないものを見た目で分ける。わかりやすさと格好よさを両立させる。
  8. 映像は必ず飛ばせる・止められるように。画面の切り替えは素早く。遊ぶ人の時間をいただいている。
  9. ギュッとしてパッと解消（緊張と解放）。予告すると合わせる楽しみが生まれる。

### 揺れ（`ride.js` の `kick`。3D のカメラだけを動かし、画面の箱・計器は揺らさない）

## 4. 計器のデザイン（騎乗中の画面）
原則 ◎：

- 数字は太い斜体。順位・時速・着順は大きく。

## 5. ゴールのあとの流れ
1. ゴール板：白い光・goal の音・cross の振動。**時は止めない・遅くしない**（持ち主の指摘 2026-10-17「ゴールしたあと止まらないで」）。**着順はまだ出さない**（左上の順位とレーダーの順位も伏せる）。
2. 流す（★ 2.4 秒 `HS.Ride.COOL`）：馬は映像の側で走り続ける。止めず、毎秒 0.8m/s ずつ駈歩の 8.5m/s（`HS.Ride.COAST_V`）まで落とし、そのまま流す（中継の画面も記録の最後のコマの後を同じように流す）。ゴールしていない馬も模擬が止まったら同じように流す。騎乗の視点ならカメラが引きながら斜め横へ回る。画面の下に小さく「[A] SKIP ▶」。
3. 着順：帯が左右から伸び、着順の数字が叩きつけられ、TIME と LAST 3F、「[A] NEXT [Y] POSE」。1着は金の帯と光、rank1 の音・win の振動。レコードなら 0.5 秒あとに RECORD。
4. 次へ：A・Enter・Start・画面を押すと結果へ。流している間に押すとすぐ着順へ（2回押せば結果まで飛ぶ）。
- 目標 ◎：ゴールから着順まで 2〜3 秒。飛ばすと 0.35 秒。着順から先は押すまで待つ（自動では進めない）。

## 8. 生き物に乗る手応え（Godot 版）
持ち主の指摘（2026-10-17、そのまま）：「（参考の動画）馬のモーションや操作感これ参考にしてブラッシュアップして　馬の操作感、ジョッキーのモデル、スタート後の挙動とか参考になると思う」「操作感は生き物に乗ってる手応えがほしい」。
柱：機械の数を動かす手ざわりでなく、自分の意思を持った馬に乗っている手ざわりにする。**入力そのものの返し（騎手の腕・計器の光・振動）はすぐ、馬の応えは少し遅れて**。騎乗中は文字を出さず、模擬の「馬の意思」の値を首・歩幅・カメラ・振動に結ぶ。

### 拍子（模擬の決まり。JS・GDScript・C++ で同じ。`S.BEAT`）
- 馬の1完歩は 7.2m。位相＝((x − v×0.05) ÷ 7.2 ＋ 馬番×0.137) の小数（描画の脚の運び・首の振り・振動・カメラの上下と同じ式。0.05 秒は、騎乗の画面が少し先の模擬を補間して見せる分）。
- 位相 0.55（首が下がって前へ伸びる所。騎手が手を前へ送る所）の前後 0.2 でしごくと**拍子が合う**（`S.ctl.up` が `'beat'` を返す）。前のしごきから 0.25 秒より短い連打・8m/s 以下は数えない。外れると続いた数が 0 に戻る（空回り）。
- 合うと：手綱の段の動きが 1.4 倍、気分の上がりが半分（馬が素直に応える）。追い出してから、拍子の合ったしごきが 2 回以上続いている間（最後から 0.95 秒以内）は、伸び ×(1＋0.05×終いの伸び)・脚の使い方 ×0.985。
- 釣り合い（`node tools/balance_bench.js beat`・`tests/extra_beat.js`。14頭・東京芝2000・気性88・300回）：噛み合った乗り方に対して、拍子に合わせて追い続けると平均着順が 0.3〜0.45 良く（勝率 先行 32→38%・差し 22→25%）、連打は変わらない。
- 2026-10-22（持ち主の決定「拍子に合わせるのはなしで」）：拍子は上手な乗り方の条件にしない。釣り合いは、ただ追う乗り方（全開）に対して拍子に合わせると平均着順が 0.4 ほど良く、連打は変わらない（`tests/extra_beat.js`）。
- 全開（2026-10-22。docs/BALANCE.md「20」）：追い出したあと、手綱の段をいちばん上（`S.DRIVE.from` 0.85 より上）にすると、脚の残りを見ずに上限の上まで走り、脚も余計に使う。早く全開にすると脚が尽きてバテる。騎乗の画面ではスタミナの升の減りの速さで読む（新しい文字は出さない）。

### 全開の知らせ（Godot 版。2026-10-22）
持ち主の決定（2026-10-22、そのまま）：「全開に入ったことの知らせ方：組み合わせでお願いします　スピードゲージも最大にすれば良いと思います」。
- 模擬は全開の度合いを `ctl.drive`（0〜1。手綱の段が `DRIVE.from` より上の分。追い出していて脚が残っている間だけ。脚が尽きる・ゴールすると 0）に置く。GDScript（`hs_sim.gd`）と C++（`hs_sim.cpp`・`hs_godot.cpp` の `drive`）で同じ。値を置くだけで模擬の結果は変わらない（一致テストの答えは同じ）。
- `godot/view/ride_drive.gd`（`ViewRideDrive`）が度合いを `vis`（色・音・振動の強さ。入るとき 0.12 秒・抜けるとき 0.45 秒・脚が尽きたら 0.08 秒で寄る）と `peg`（速さの計器の振り切り。全開の間は 1）にならし、入った瞬間（enter）・段を下げて抜けた（exit）・脚が尽きて切れた（spent）を返す。
- 返し方（3 の表）：計器の色（`ride_hud.gd` の速さの計器と手綱の帯。色は金の続きの白熱。悪い＝赤・競り合い＝橙とは混ぜない）・速さの計器の振り切り・音（`godot/view/ride_sfx.gd`。その場で波形を作る。音のファイルは使わない）・振動（`ViewRideInput.fx("drive")`・`step_pulse` の drive）。入った瞬間は 4 つ（計器・音・振動・揺れ）で返す。
- バテと混ぜない：脚が尽きると全開の知らせはすぐ消え、スタミナの赤い点滅だけが残る。

### ゲートを出たあと（模擬の決まり。JS・GDScript・C++ で同じ。`S.START_STYLE`・`S.FAN`）
- 横一線から全馬が一気に出て、出だしの加速が脚質で違う（逃げ ×1.18・先行 ×1.07・差し ×0.96・追込 ×0.88）。4 秒で先頭から 逃げ 2.5m・先行 3.4m・差し 8.1m・追込 9.3m ほどに分かれる（前は 3 秒で 逃げ 3.0m・追込 4.4m と、ほぼ横一線のままだった）。
- スタートから 250m までは、内へ寄る速さを 0.2 秒に 0.1 進路（毎秒 0.5 進路）までにする。外の枠の馬は数秒かけて内へ寄りながら縦長の群れになる。自分の馬も、進路をまだ触っていなければ同じ速さで寄る（触ればすぐ動く）。
- 走破タイムはほぼ変わらない（東京・40 回の平均：芝2400 143.22→143.14 秒・芝1200 66.73→66.70 秒）。
