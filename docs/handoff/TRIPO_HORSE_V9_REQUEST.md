# 馬モデル v9 の依頼（Codex へ）

v8（`codex/tripo-horse-handoff` の `artifacts/tripo-horse-v8/`）を、ゲームの試作の場面に取り込んで、v7・いまの馬と並べた（2026-10-24。取り込んだ枝は `claude/tripo-horse-v8`、比べの絵は同じ枝の `docs/shots/compare/tripo_v8/`）。

持ち主の判断：「今度は首短いような」「首の長さを気にするのではなく実際の馬のようにしてほしいだけです」「アニメーション例はわたしてあります」（2026-10-24）。

## いちばん大事なこと：数を合わせるのをやめ、手本の動きに合わせる

v4 から v8 まで、首は「短く太い」と「長すぎる」の間を行ったり来たりした。原因はこちら（Claude）の依頼の書き方にある。持ち主の見た目の指摘を、毎回「首の上の線を何 m に」という数の目標に訳して頼んだ。そのため、数は合っても馬らしく見えない形ができた。

- v8 の依頼では、立ち姿の首を 0.56〜0.62m にし、走りの首は「v7 より短く」とだけ書いた。下限を書かなかった。
- その結果、v8 は走るときに首が縮んだ。首の上の線は、立ち姿の 0.563m から襲歩で 0.408m になり、28% 短い（v7 で縮んだのは 11%）。1完歩の8コマのどのコマでも、首が詰まって見える。
- 本物の馬は、走るときに首を前へ伸ばす。頭は、首を縮めて下げるのではなく、首の角度で前下へ出る。

**v9 では、v8 の依頼文の数の目標（首の上の線 0.56〜0.62m・頭の 1.0〜1.1 倍・「v7 より短く」・うなじの高さ 1.66〜1.72m）を全部取り下げる。** 代わりに、持ち主が渡した手本（下の「手本」）に、立ち姿・常歩・駈歩・襲歩のどれも、横から重ねて見て同じに見えることを合格にする。数は測って報告するだけにし、合格の条件にしない。

## 手本

- **持ち主が渡したアニメーションの例**：ギャロップの12コマの連続絵と、走りと歩きの動画2本。持ち主から直接受け取っているもの（有料の素材と出どころの分からない動画なので、リポジトリと納品物には入れない）。v7 の依頼文（`docs/handoff/TRIPO_HORSE_V7_REQUEST.md` の 2b・2c）に、そこから読み取った形と動きを書いてある。
- 手本どうしで迷ったら、持ち主の例を優先する。v7・v8 で使ったパブリックドメインの写真（Ridgeway 1905 の図129・Muybridge の plate 626）は、補いの資料として使ってよい。

## v9 で直してほしい所

### 1. 首と頭を、手本と同じ形・同じ動きにする（いちばん大事）
- 横から見て、首の長さ・太さ・付け根の位置・頭の大きさと向きが、手本の馬と同じに見えること。立ち姿・常歩・駈歩・襲歩のすべてで。
- 走りで首が縮まないこと。1完歩のどのコマでも、首の見えの長さは立ち姿と比べて手本と同じ変わり方にする（手本で伸びるなら伸ばす）。
- 頭の上下・前後の動き（うなずき・前へ出る時機）も、手本の1完歩に合わせる。

### 2. 合っていることを、重ねた絵で見せる
- 手本の各コマと、v9 の同じ時期のコマを、き甲の高さをそろえて横から重ねた絵（半透明の重ね、または輪郭線）。
  - 襲歩は、手本の12コマすべて。
  - 駈歩・常歩は、手本の動画から1完歩を8コマ以上。
  - 立ち姿も1枚。
- 同じ並べ方で v8 も重ね、v8 と v9 のどちらが手本に近いかを見せる。
- 手本の絵と動画は持ち主の素材なので、重ねた絵は確かめに使うだけにし、納品物（`artifacts/`）とリポジトリには入れない。持ち主に見せる絵は、手本を輪郭線だけにしたものにする。

### 3. v7・v8 で良くなった所は変えない
- 常歩のうなずき（1周期に2回）と、WalkNeckCorrective・RaceNeckCorrective の2つの補正。
- 走りの胴のしなり。首の付け根が太く、喉へ細くなる三角形の形。
- 正面の顔の鼻の穴と口（COLOR_0 とシェーダの差分）。
- 接地と約束：1完歩 7.00m・周期 0.45 秒・その場走行・蹄が滑らないこと。
- 取付点（`Saddle`・`Stirrup_L/R`・`Bit_L/R`・`Withers`）と `saddle-track.json`・`attachment-tracks.json`。頭が動いたら Bit の軌跡は v9 で出し直す。
- 重さ：19,168 三角形・骨 54 本から大きく増やさない。
