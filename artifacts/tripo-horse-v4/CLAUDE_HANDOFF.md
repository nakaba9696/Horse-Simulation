# Tripo Horse v4 引き継ぎ

依頼元: `claude/lucid-ptolemy-j204a3` の `docs/handoff/TRIPO_HORSE_V4_REQUEST.md`（取得したコミット `92d9606b7add652e63aebef10240143d40e506fb`）。依頼の写しも同梱しています。

V4は**比較・取り込み用の試作素材**です。ゲームのコード・データは変更していません。本採用の判定は、既存の馬・騎手と同じレース・同じ時刻で比較して行ってください。受け渡しブランチ全体のマージは不要です。

## 依頼への対応と実測

|項目|V4の対応・確認|
|---|---|
|体の上下と滞空|周期0.45秒。4蹄すべてが地面から1.5cm超離れる時間は20%。き甲の上下は11.87cm。最小位相0.683、最大0.900で、最大は滞空中。首・頭に遅れを付けた揺れを追加。|
|完歩|参照倍率2.6で、接地時の蹄領域の重心から測った完歩は約6.99〜7.00m。前進のルート移動なし。|
|首・喉・肩|脚の影響を解剖上の高さで制限し、首から胸・肩に広い補正形状を追加。元のUV境界の重複頂点を統合し、補正形状の法線も再計算。側面28時点を同梱。下の「残る限界」も参照。|
|たてがみ・尾|耳の後ろまでregion 1を延長。前髪6、たてがみ32、尾12の立体的な房を追加（計50房・500三角形）。元の彫刻状の毛の形も残る。|
|立ち姿・常歩|`Stand_Loop` 3秒、`Walk_Loop` 1.2秒。耳・尾の微動／4拍の常歩。Stand/Walkでは首補正0、Raceでは1。切り替え後にStandへ戻ることをGodotで確認。|
|騎手用の点|背の骨に追従する `Saddle`、`Stirrup_L/R` を追加。`saddle-track.json` に走行1周期を60fps・28標本で収録。|
|頭絡・手綱用の点|別メッシュ・別材質で額帯、頬革、鼻革、はみ・リングを追加。`Bit_L/R` は頭の骨に追従。region 7は流用していない。|
|体長|元モデルを前後方向だけ約3.73%短縮。中立形状の鼻先〜尾端は倍率2.6で2.45m。高さは縮めていない。走行中の鼻・尾の動きで見掛けの全長は変わる。|
|重さ|全体19,358三角形（馬18,818、革432、金具108）。V3の18,320から約5.7%増。骨54本を維持。GodotのLOD生成は有効。ゲーム内CPU時間は未測定。|

数値の原本は `motion-validation.json`、`geometry-report.json`、`godot-validation.json`。滞空は蹄の最低点、き甲は `Spine_7` の頭（`Withers`ノード）で測定しています。表の完歩は接地時の重心速度からの回帰で、蹄の全頂点が完全に滑らないという意味ではありません。走行中の最低蹄位置には最大約2mmの地面への入り込みがあります。

## 変えていない約束

- GLB座標は **+Y上、-X前**。ゲームの親Y回転+90度の扱いは維持。
- `RaceGallop_Loop` 0.45秒、参照倍率 `S=2.6` で完歩 `L=7m`。
- `L=7*S/2.6`、走行再生倍率 `v*0.45/L`。例えば16m/sなら約1.02857倍。
- UV2は `region=floor(UV2.x*8)`、`leg=floor(UV2.y*8)`。schema version 1を維持。色境界・房の領域は見直したが、符号化・領域番号・脚番号は変更していない。
- UV2のライトマップ上書き禁止。GLB内の法線画像を保持。
- `RaceNeckCorrective` は走行1、Stand/Walk 0。54本の骨の名前・構造は維持。

## Godot取り込み

まず独立した `preview/` をGodot 4.6で開くと、初期状態はStandです。側面・正面・背面・斜め、毛色、領域表示、速度、一時停止、3クリップ、取付点表示を切り替えられます。

ゲーム側では既存の `godot/proto/tripo_horse/` にV4を別名で置いてください。取り込み設定は以下を確認してください。

```
meshes/light_baking=0
meshes/generate_lods=true
animation/fps=240
animation/remove_immutable_tracks=false
```

新しい場所に一度インポートした後、`python tools/configure_godot_import.py 対象.glb.import` でこれらのパラメータだけを更新できます。別のパスの `.import` を丸ごとコピーすると依存先がずれるため、ゲーム側ではそのままコピーしないでください。

Godotでの名前は `RaceGallop`、`Stand`、`Walk`、すべて `LOOP_LINEAR`。GLBの各クリップは163トラック（54骨×位置・回転・拡縮＋補正形状）を持ちます。定数トラックを残し、前の姿勢が混ざったまま残るのを避けています。

Stand/Walk/Raceの切り替えは0.18〜0.25秒程度で補間してください。プレビューは0.18秒です。morphの値はクリップに含まれるので、外部コードで常時1に固定しないでください。常歩の参照完歩は倍率2.6で1.6m、周期1.2秒です。常歩も移動速度と合わせるなら `v*1.2/(1.6*S/2.6)`。

**毛色シェーダは `Horse` にだけ適用してください。** `BridleLeather` / `BridleMetal` は独立材質です。全メッシュへの一括 material_override は頭絡の材質を壊します。毛色の塗り分けはベースの領域であり、個々の実馬の白斑を再現したテクスチャではありません。

## 騎手・手綱への接続

- `Saddle` / `Stirrup_L` / `Stirrup_R`: 背の `tripo::Spine_3` に追従。
- `Bit_L` / `Bit_R`: `tripo::Head_5` に追従。はみのリング中心と一致。
- `Withers`: `tripo::Spine_7` に追従する測定用の点。
- Godotの骨名では `::` が `__` に変換される。ノード名は上記のまま。

GLBのノードに騎手の基準を置くのが基本です。鞍・あぶみの**実物メッシュは付けていません**。これらは騎手モデルに合わせるための初期取付点で、既存騎手の臀部・膝・足先に合わせた調整はゲーム側で必要です。手綱もゲーム側でBitから手へつないでください。

`saddle-track.json` はRaceの1周期（0〜0.45秒、終端含む28標本）。`attachment-tracks.json` は3クリップ全て。`socket-rest.json` は中立形状の点です。各標本に6点の `position_model`、`quaternion_xyzw`、`forward_model`、`up_model`、`pitch_degrees` を収録しています。

位置は**拡縮前のGLBモデル空間**、回転は同じ空間のxyzw。モデルの親変換（倍率、+90度回転、ゲーム中の移動）を一度だけ適用してください。JSONの位置に2.6を掛けてから、更に倍率2.6の親に入れると二重拡縮になります。周期端をまたぐときは位置を線形補間・回転をslerpしてください。

Godotのキー最適化によるJSONとの最大差は、Saddle約1.31mm、左右あぶみ約1.39mm、はみ約5.87mm、Withers約2.49mm（倍率2.6）、角度約0.26度。ノードへ直接接続すればこの別経路の誤差は生じません。JSONを使う場合はこの誤差を前提にしてください。

## 確認と残る限界

- 最終GLBを読み直して、3クリップ各241位相で蹄、き甲、ループを測定。ループ端の頂点差は0。
- Godot 4.6.3 headlessで3クリップ各1,920標本・20周期、骨の有限値、ループ、morph値、Stand復帰、UV2の8領域・5脚番号、6取付点を検査。
- `renders/` に走行側面28時点、正面・背面各4時点、Standの3方向、Walkの8時点、首元・領域表示。配布画像は1600×1000のJPEG。Blenderの再読み込みではmorphに追従しないカスタム法線を消し、評価形状から法線を再計算して描画している。GLB自体にはbase/morph法線を保持。Blender CPU Cyclesの画像であり、ゲーム画面のスクリーンショットではない。
- 喉〜胸の主な折れと陰影は改善したが、元モデル由来の頬・肩・たてがみの彫刻状の凹凸や、毛色境界の角張りは残る。**全コマで完全に皺がない完成形、とは判定していない。** 28コマと首元の拡大で比較し、本採用前のアート調整として扱ってほしい。
- 房は少数の立体形状。毛の揺れ、耳や尾の高度な物理、実写の走法への一致は未実装。
- 同じゲーム画面での騎手との干渉、LODの見え方、GPU表示、CPU時間、16頭レースの負荷は未確認。ゲーム全体の回帰テストも完了していない。ゲーム側で比較・計測してから採否を決める。
- 元素材はユーザーがTripo Proで生成した提供GLB。追加した房・頭絡・アニメーションは今回作成した形状・動作で、外部の馬モデルや動画を流用していない。利用権の記録はユーザーのTripo契約に基づき、ゲーム側の `assets/CREDITS.md` に生成元・加工内容を記載してください。
