# Claude引き継ぎ：競走用の動き・毛色領域を追加した馬 v3

## v2からの変更
ユーザーが共有したClaudeの評価「完歩が短い、首が高い、脚の伸びが小さい」を受け、動きを作り直した。ゲーム側の現行馬の7.2mという値は、こちらでは再計測していない。

- 参照倍率2.6で約7m/周期。周期0.45秒、約2.22完歩/秒。参照速度15.56m/s。
- 脚の振幅を大きくし、右後→左後→右前→左前→浮遊の順で目標軌道を設定。
- 首を付け根から前へ倒し、頭側は別の角度で鼻先が下がりすぎないよう調整。
- UV2に毛色領域、脚ID、元の脚高さ、たてがみ境界のブレンド量を記録。
- Godot向けの毛色シェーダーと鹿毛/栗毛/芦毛/領域表示のプレビューを追加。
- 首の折れを軽減するRaceNeckCorrectiveを追加。値1で走行中に使用。

## 入っているもの
horse-gallop.glb（最終成果物）、horse-gallop.blend（編集用）、source-rigged.glb（未変更の元データ）、preview/（独立Godot 4.6プロジェクト）、tools/（再生成と検証）、gallop-preview.mp4、bay.png/chestnut.png/region-debug.png、各種JSON記録。

メインゲームのコード・データは変更していない。既存馬を上書きする前に、独立した試作シーンで比較すること。

## 完歩と速度の取り込み契約
GLBはその場走行。ルートが7m前進するアニメーションではない。「7m」は、接地中の蹄の後退速度から、親ノードが前進すべき距離を1周期へ換算したもの。

基準: 親の均一倍率S=2.6、周期T=0.45秒、完歩L=7m。
- Sを変えた場合の完歩: L = 7 * S / 2.6。
- 任意のゲーム速度vに合わせる再生倍率: speed_scale = v * 0.45 / L。
- S=2.6、v=15.56m/sならspeed_scaleはほぼ1。
- 旧v2の周期0.8秒やクリップGallopを流用しないこと。

今回、倍率2.6で接地中の蹄重心の速度を回帰して測った完歩は各脚6.989〜7.003m。名目値だけを7へ変えたものではない。stride-measurement.jsonに各脚の記録あり。

GLBはY-up、前方-X。ゲームが前方+Zなら親ノードのY回転+90度を起点に確認。骨の向きは変えない。実馬の体格差に合わせてSを変えたら、上のLも合わせて更新する。耳までの全高を体高として扱わない。

## アニメーションと首の補正
GLBのクリップはRaceGallop_Loop。Godot 4.6.3の自動取り込み後の名前はRaceGallopでLOOP_LINEAR、長さ約0.45秒。実際のget_animation_list()を確認する。

54ボーン。旧42ボーンの動きは直接使えない。元データは240fps・108区間で作成してベイクした。検証画像/動画は60fps。

RaceNeckCorrectiveは走行時の首の局所的な折れを和らげる補正形状。GLBの既定値1に加え、走行クリップに値1のトラックを含む。Godotでクリップを再生した後に値1になることを検証した。表示前に必要ならMeshInstance3D.set_blend_shape_valueで明示的に1へ設定する（preview.gd参照）。別の立ち姿や常歩を後で追加する際は、その姿勢に応じて補正を0へ戻すか調整する。全姿勢に汎用の補正ではない。

## 毛色用の領域データ
属性はTEXCOORD_1 / GodotのUV2。通常のUV0・法線テクスチャは保持。JSONのcoat-region-schema.jsonとpreview/coat.gdshaderが正。
- region = floor(UV2.x * 8)
- 0 胴、1 たてがみ、2 尾、3 蹄、4 鼻先、5 目、6 顔の白徴候補、7 耳内側候補
- leg = floor(UV2.y * 8)
- 0 脚以外、1 左前、2 右前、3 左後、4 右後
- 元の高さ（モデル単位） = clamp((fract(UV2.y*8)-0.15)/0.7,0,1)*0.45
- たてがみの塗り分け量 = clamp((fract(UV2.x*8)-0.1)/0.8,0,1)

領域IDは面ごとに固定し、たてがみの境界には補間用の値を持つ。静止時に設定したUVなので骨の動きに追従する。UV2をライトマップ用に生成し直すとデータが壊れる。自動ライトマップUV生成を行わず、他の用途へ上書きしないこと。

色を出すにはpreview/coat.gdshaderをShaderMaterialとして使うこと。GLB単体の元材質はグレーで、領域データだけで自動的に鹿毛になるわけではない。preview.gdに割り当て例あり。normal_textureとnormal_strengthを元材質から引き継ぐ。胴/たてがみ/尾/蹄/鼻先を別色にできる。

sock_heightsは左前/右前/左後/右後の白い脚の高さ（モデル単位、無効は0）。face_markは候補領域へ白色を出す簡易機能。これらは史実馬の白斑を再現したものではない。顔・目・耳の候補や毛の境界は空間的なシードであり、最終の絵として精密に手塗りしたマスクではない。たてがみ/尾の一部に境界の粗さが残るため、必要ならBlenderのCoatRegions UVを調整すること。

## 最終成果物の検証
- 書き出したGLBをBlenderへ読み直し、全28時点を1600×1000の側面画像で確認、正面/背面も各4姿勢確認。
- ループ端の頂点差の最大: 2.97e-07モデル単位。
- 193時点で脚の接地を確認。接地区間の重心高さの振れ幅の最大は0.000841モデル単位。蹄領域の最低点は-0.000121付近。微小なめり込み/滑りはゼロではない。
- 193時点で蹄領域どうしのAABB重なり0件。全身の自己衝突判定ではない。
- 元の辺長0.002以上の辺の最大伸長率6.36。首・肩・内股などには局所変形が残る。大きな針状の蹄の伸びは目視した姿勢で見られないが、破綻ゼロの保証ではない。
- 首の比較用にHead_5位置を計測。き甲側の骨に対する平均前出し量はv2の0.179からv3の0.283モデル単位。平均高さ差は0.179から0.107へ低下。表面の厳密な解剖学的位置の測定ではない。
- GodotでUV2、8領域・5脚ID区分を検証。頂点数はUV境界等で分割され18220。首の補正値1も再生後に検証。
- Godotで20周、1,920時点、全54ボーン座標が有限。周回位置ずれは最大5.49e-08。脚の動き、色パラメータ変更、速度・停止・視点切替の処理を確認。
- シェーダーとUIはheadlessでロード/操作を確認したが、実際のGodotデスクトップ画面の描画は未確認。添付の毛色画像はBlenderによる確認画像。
- tools/rebuild.pyで別ディレクトリに最終GLBを再生成した。元GLBから再処理できる。
- ゲーム全体の回帰テストは未完了。QUICK=1 node tests/run.jsは120秒でタイムアウトし結果を得られなかった。ゲーム本体は変更していない。

## 見た目の確認と限界
基準にしたのはユーザー経由のClaudeの指摘と約7mという目標。共有されたYouTubeは403で未視聴であり、実写の走りに一致させたものではない。動画なしで進めるというユーザー指示のもと、手続き的に作成した試作である。

1600×1000の確認画像では、脚の伸びと前へ倒した首がv2より強く出る。首・肩の造形、たてがみの境界、脚を畳む自然さは追加の美術調整余地がある。採否は現在の馬と同じレース画面・速度で並べて判断すること。UI/騎乗全体の合格点を今回の単体素材だけで付けたものではない。

ゲーム統合、地形追従、速度ブレンド、実馬ごとの体格、精密な白斑、ブリンカー/シャドーロール、騎手は未実装。
